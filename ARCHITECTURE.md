# Architecture

The package has five boundaries: a certified SDK environment, a durable SDK call ledger, a bounded JSON action interpreter, model transports, and native pm host commands. The workspace argument is the explicit tracker root. No operation discovers an ancestor tracker, writes item documents directly, starts another coding agent, executes model-supplied code or opens linked file contents.

`readCorpus` calls `PmClient.listAllComplete({includeBody: true})` and independently certifies the result. All statuses, full metadata and bodies are read before applying the scope. Every source row except execution calls and generated questions is sorted by id and frozen in the root checkpoint. Environment operations intersect filters with that snapshot; result objects are copied before delivery. A complete-list certificate describes the source read, not the size of a filtered response. History is read through SDK history APIs, chain-verified, and bounded by the source item's snapshot timestamp. Missing or invalid history refuses.

## Ledger schema

Every call is a Task tagged `rlm:call`. Root depth is zero; its parent is a question item. Generated questions are tagged `rlm:question`. A child's parent is the calling call item, never the question. SDK claims identify active work; result evidence is an idempotently appended `RLM result:` comment. The engine closes and releases call items after completion. Development Features and the package Epic are separate records and stay open for orchestrator verification.

| Registered field | Type | Meaning |
| --- | --- | --- |
| `rlm_run` | string | Root call id |
| `rlm_depth` | number | Root zero, child parent plus one |
| `rlm_model` | string | Stable model identity |
| `rlm_prompt_digest` | string | SHA-256 of exact subgoal, slice and resolved settings |
| `rlm_tokens_in` | number | Sum of recorded-or-estimated model input usage for this call |
| `rlm_tokens_out` | number | Sum of recorded-or-estimated model output usage for this call |
| `rlm_state` | string | Root-only v2 digest manifest; legacy inline v1 remains readable |

Fields are registered with the extension API and persisted with SDK schema mutations. Standalone SDK consumers use the SDK's native schema-field options through `client.run`; the `--field` assignment path requires an active extension registration even when the schema is persisted. All item, claim, comment, status and settings changes use the public SDK.

The hydrated checkpoint contains question, resolved limits/transport configuration, scope, immutable source snapshot, complete-read certificate, reserved token total and the ordered call graph. V2 storage separates payloads from the root manifest as described below. Each call contains deterministic id, parent, depth, subgoal, exact slice, digest, ordered model steps, and either an optional result or a terminal typed failure code and reason. A typed completion-hook refusal after a durable result has a separate `completion_refusal` receipt; later digest reuse returns the result without repeating that hook. Each step contains its exact prompt, current model charge in `reserved`, an optional `settled: true` marker, an optional model response with usage, and an optional tool observation. Settings store only a credential environment-variable name, never its value.

Every child of a successfully finished root reaches a terminal recorded state: completed with a result or failed with typed refusal evidence. A typed failure in a materialized child is checkpointed, recorded as an idempotent `RLM refusal:` evidence comment, closed and released before its parent receives the refusal. Raw transport messages are never persisted as refusal evidence.

Root failures remain resumable interruptions. Legacy or corrupted checkpoints with a completed root and an unterminated child fail closed as incomplete on resume; they are never silently reported as recovered.

## Reservation and recovery invariants

1. The root item is the single serialization point for graph and budget checkpoints. SDK item mutation provides atomic item/history publication. A process-owned runtime lease serializes execution of each run. Lease acquisition/recovery is protected by a short SDK lock; a live PID refuses competing execution. PID reuse fails closed. If a process dies inside that short lock, retry after its 60-second stale window. Runtime lease files are excluded from version control.
2. A child is inserted into the root call graph and checkpointed before materialization or inference. Its id is derived from the root id and graph position. Materialization first checks the certified corpus, so a crash between creation and later bookkeeping cannot duplicate an item.
3. Before each inference, the engine checks context and total budget and atomically saves a reservation with the step. It reserves prompt UTF-8 bytes plus sixteen bytes per allowed output token. It performs no inference until that reservation is durable. Resuming that step reuses its reservation.
4. Model accounting has two phases. A validated response settles the pending worst-case reservation to recorded model input plus output counters (provider reports or conservative fallback estimates): the unused allowance is subtracted from the run total, the step charge becomes those recorded counters, and `settled: true` plus the response are published in the same atomic SDK checkpoint. There is no durable intermediate state between response recording and settlement. A crash before that checkpoint leaves one worst-case reservation with no response; resume reuses it until the response is re-recorded and settles once. A crash after that checkpoint reuses the response and never settles it twice. Recorded legacy responses without a settlement marker are settled together in one checkpoint before execution resumes. Usage above the reserved allowance refuses as a typed model contract error. Malformed action JSON, including an empty response string, is a recorded refusal and pays its recorded-or-estimated model usage. Non-string response text is invalid. External provider billing cannot be made exactly once: an inference whose response was lost can be repeated.
5. Every observation passes the ledger privacy check inside the tool-refusal boundary before charging or persistence. A private historical value becomes a recorded `invalid` refusal without retaining its content; resume and replay reuse that refusal. Successful reads charge their delivered data before storing the observation. Failed reads deliver no partial result. The run total includes delivered-read estimates, settled model usage and outstanding worst-case reservations. Read charges are not refunded. Model refunds depend only on the atomic response checkpoint, never on a later cleanup operation. Maximum call count includes the root; maximum depth counts edges below it.
6. Child lookup uses calling parent plus prompt digest. A terminal failed digest rethrows its recorded typed refusal without inference; a completed digest returns its recorded result and repairs missing comment/status evidence through idempotent SDK operations. It never calls the model again. The SIGKILL test targets the interval after a child result is durable and before its parent observation is durable.
7. A finish result is checkpointed before comment, usage, closure and release. Resume reconciles all terminal call evidence before root execution. The runner reloads the checkpoint after acquiring its lease so a competing completed executor cannot leave it using stale state. Custom users of `RlmEngine.spawn` must hold the same lease around their entire state transaction and await calls sequentially.
8. Replay is read-only. It re-parses recorded model outputs, re-executes environment reads against the frozen item snapshot and timestamp-bounded history, traverses digest-selected children, checks recorded tool observations, terminal child refusal codes/reasons and child results, and requires the final finish answer to match the checkpoint byte-for-byte. Missing finishes, missing children, changed observations/results and unreachable call records fail replay. No model endpoint is contacted.

Partitioning serializes each full item, then packs escaped JSON fragments by binary search against the exact byte estimate of their envelope. A single oversized item can span slices; offsets and text reconstruct its original JSON exactly. Child scope validates every fragment against the parent's full authorized items or inherited fragments. Only completely represented items become child tool-readable items; partial fragments are prompt context and can be subdivided without widening scope.

The reservation bound applies to logical execution, not remote model billing or source bytes read internally to certify a corpus. Storage v2 keeps `reserved_tokens` exclusively in one atomic root manifest with the run id and snapshot/transcript digests. In-memory/public `RlmState` remains version 1. `RlmBlobs` stores exact UTF-8 JSON bytes under their SHA-256 digest in the durable tracker `rlm-blobs/` directory. The snapshot is independent of run metadata. The transcript references call payloads; each call references its slice, prompts, responses and observations. Revisions reuse unchanged payloads. Hash-verified hydration precedes the existing settings, call, slice and step validation.

Save and root materialization write all referenced immutable payloads before updating the manifest through the SDK. Reusing a digest checks the existing bytes and refuses corruption instead of overwriting it. The manifest atomically binds the new reservation total to exactly one transcript/snapshot pair. A process-owned storage lease serializes publication and collection across runs. Hydration uses no read-side lease writes: every committed manifest remains rooted through current state or append-only history, including a version read before a concurrent save. Its admission lock is short-lived; a dead storage owner is recoverable without waiting for the duration of a long collection. A live owner causes bounded waits and a typed busy refusal after one minute. Call inference still uses the independent per-run lease.

Legacy v1 hydration passes the inline JSON directly into the same validator. Read-only replay and tree leave it unchanged; an explicit save performs lazy migration. No old item history is rewritten. GC certifies the current corpus, verifies every historical stream and marks every blob traversed by present and historical manifests, including histories of deleted roots. Unknown storage versions abort marking before deletion. Only after a successful full mark does it remove unreachable digest files and abandoned atomic blob temporaries. It preserves unrelated files and never prunes history. Removing current roots alone does not make their historical payloads collectible. The SDK does not transact arbitrary external tracker edits with this lease; backup/restore tools must keep blobs with their references and coordinate with writers.

Certified scans still grow with item/run count, and hydrating one run still reads its snapshot and transcript. New prompts can themselves contain growing transcripts; exact-byte content addressing cannot deduplicate different prompt prefixes. Historical manifests/call metadata remain append-only. Storage benchmarks isolate these bounds from correctness, provider quality and end-to-end throughput. SIGKILL drills stop in real blob and root atomic temporary-file writes, compare the preceding state and reservation coordinate, then resume/replay. SDK item TTL locks require the tracker's stale-lock recovery policy before resume. Crash fixtures use one-second item-lock TTLs with automatic stale recovery; these tests do not assert host power-loss durability.

## Local verification

The scripted model lives only in tests. Its tracker is always a real SDK-created scratch workspace. Actual HTTP servers exercise Ollama and compatible wire formats. A real worker is killed with SIGKILL after one completed child checkpoint; a new process resumes and is compared with an uninterrupted run. Completed-child inference count, answer bytes, reservations and SDK parent/depth rows must agree. Separate destructive behavioral mutations are confined to the package's own source and restored byte-for-byte in `finally` blocks.

The live eval independently verifies public source visibility and the source revision, copies only committed regular tracker files from that revision, explicitly pins loopback Ollama transport, computes truth before any run, excludes generated ledger/question rows from context, and retains public aggregate measurements. It reports incorrect results and refusals honestly. CI, coverage, artifact contents, provider quality, remote reviews and publication are distinct claims; this package is not yet published or deployed.

The model protocol exposes compact partition references instead of repeating all fragment text in the parent transcript. References select a successful partition step and slice index; resolution recomputes exact fragments from the frozen parent scope. The exported environment partition API continues to return full lossless slices. Replay accepts the earlier full-slice partition receipt as well as the compact protocol receipt, comparing either exactly against the frozen source. Delivered observations, including completeness receipts and spawn results, must fit the exact projected next prompt before being charged or retained.

Loaded checkpoints are untrusted tracker data. Resume, tree and replay validate call objects, ids, depths, step arrays, fragment slices, response usage and complete transport settings before using them. Invalid shapes or unsafe checkpoint settings refuse with `incomplete`, before constructing a model adapter. The same settings validator enforces HTTPS for remote OpenAI credential transport and permits local loopback HTTP.

The lean call tree exposes `reserved_tokens` (settled usage plus any pending model reservations) and `used_tokens` (recorded-or-estimated model input plus output), so a pre-response interruption visibly retains a reservation with no recorded usage. Endpoint redirects are rejected before forwarding prompts, and non-OK response bodies are canceled. Replay refuses missing or malformed spawn observations with a typed `replay` error. Public evaluation Git subprocesses disable replacement objects as well as checking archive paths and blob bytes.

Privacy checks resolve workspace paths, omit filesystem-root ancestors, and retain the workspace itself even when it is a root. Windows drive and UNC paths are checked with Windows semantics, case-insensitively and with both separators, regardless of the current platform. Secrets retain exact matching. Git and npm subprocess boundaries remove excluded environment keys case-insensitively before applying isolated configuration. The offline evaluation formatter replaces exactly one ordered marker pair and validates it before writing report artifacts; prose headings do not locate generated content.

Every SDK read has a shared typed failure boundary, including full-list certification, history parsing/verification, schema and settings reads, and runtime lease reads. Unexpected read/parse exceptions become sanitized `incomplete` refusals; existing typed validation refusals retain their codes. List, search, get and comment projections use the frozen certified snapshot, so they cannot perform an unguarded live SDK read. A history failure inside a child becomes a recorded tool refusal, allowing the child to finish and replay/resume normally.

Token counters are accounting values, not an assertion about provider billing: HTTP adapters use provider counters when supplied and conservative UTF-8 byte estimates otherwise. Run and tree results label this with `token_usage: reported_or_estimated`. Reservations additionally include worst-case pending allowances and byte-estimated delivered reads. Eval provenance labels distinguish these from exact observed counts, exact truth-derived scores, measured wall time and configured limits; the historical artifact cannot separate per-response usage provenance retrospectively.

Comment reads are part of the certified full-item snapshot. `comments(add, ifAbsent)` is an evidence mutation: its unexpected failure must abort execution rather than become a recoverable read refusal. The completed child result remains checkpointed, the parent observation remains unfinished, and resume retries evidence reconciliation without another child inference. This distinction prevents a successful root from hiding an unfinished evidence write.

## Typed aggregation

`RlmContext.aggregate(action)` accepts `count`, `sum`, `distinct`, `group_count`, `argmax` and `argmin` requests. The engine routes them through the same observation projection, token charging, checkpoint and replay path as reads. The root sees only its frozen selected snapshot; children see only fully covered items in their authorized slices. No code, expression evaluator, filesystem query or live tracker reread runs inside an aggregate.

Filters have the existing exact intersection semantics. Numeric expressions are one own field identifier or `len(field)`. The latter measures UTF-8 bytes of text; missing/null text counts as empty. Other nontext values refuse. Numeric fields must be finite numbers; missing fields, unsafe integer inputs/results and overflow refuse. Fractional arithmetic follows JavaScript IEEE-754 semantics. Empty sums/counts are zero. Extrema return all tied ids in codepoint lexical order, or an empty array. Distinct and grouped counts support scalar values only, normalize absent values to null, and sort by type (null, boolean, number, string), then value: false before true, numeric ascending order, and UTF-16 code-unit string order without locale dependence. New checkpoints record `aggregate_version: 2`; missing or explicit v1 retains the original JSON-encoding key order during replay and resume, including new reads after interruption. Unknown aggregate versions refuse checkpoint loading. This version is independent of parser and storage schema versions. Group results are `{value,count}` arrays, so arbitrary string keys cannot mutate object prototypes.

Every aggregate returns `{data,estimated_tokens,complete_list}`. `estimated_tokens` is the conservative serialized-data byte estimate used by reads. The entire observation must fit the next prompt before the ledger charges or retains it. A refused model step still consumes its settled model budget. Replay recomputes delivered aggregates against the frozen snapshot and compares the complete observation byte-for-byte.

See [the diagnosis](docs/ACTION-DIAGNOSIS.md) for the historical evidence gap and synthetic versus recorded regression cases. Release remains disabled.

## Versioned action contracts

Checkpoints carry `parser_version`. Missing versions select the original strict v1 JSON parser, including its original action kinds. Explicit v2 selects the tolerant pre-schema validator. New runs record v3. Replay, resume (including fresh inference), and partition-reference resolution all use this value; replay does not migrate or rewrite old checkpoints. Unknown versions refuse checkpoint loading. Parser versions are independent of the checkpoint storage schema version. Replay and resume recompute parse refusals from recorded model output using that version and compare both the refusal code and message with the recorded observation. A mismatch raises a typed `replay` integrity refusal naming the call and zero-based step, before resume reconciles evidence or feeds recorded text into a new prompt. Original v1 code-only receipts remain valid: their codes are compared, and any recorded reason must also match. Newer parser versions require both fields. Read-only replay preserves checkpoint bytes.

`src/action-schema.ts` defines the current discriminated union once. The exported JSON Schema is interpreted by the runtime validator and sent as Ollama `format`. Unknown properties, unsupported filters, invalid expression grammar and wrong operand types refuse. Optional filters normalize to `{}`. Slice reconstruction, field availability, scope authorization, range relationships and budget checks remain environment semantics; a syntactically valid action can still receive a charged tool refusal. These semantic checks cannot be expressed entirely in ordinary JSON Schema.

OpenAI-compatible requests use `response_format: {type:"json_schema",json_schema:{name,strict:true,schema}}`. Their strict schema is generated from the same definitions: the action union is nested inside `{response: ...}` because strict OpenAI schemas prohibit a root union. Optional properties become required nullable properties; the adapter removes only optional nulls and unwraps only a fully validated transport response, then the engine validates the canonical action again. The compatible wire schema recursively omits `minLength`, `pattern`, `minimum` and `maximum`, which strict structured outputs do not support consistently across endpoints and fine-tuned models. One wire schema serves every compatible model without name-based detection. The full action schema and strict wrapper schema remain unchanged for local validation (`schemaAction` / `parseAction` and wrapper decoding), so violating an omitted constraint still refuses locally. Stuffing requests have a separate `{answer:string}` contract, with its wire schema derived through the same conversion. Legacy resume requests retain their original JSON transport settings. Endpoints ignoring the contract retain the tolerant extraction fallback, and neither truncation nor a provider refusal is treated as a valid action.

[Ollama's structured-output documentation](https://docs.ollama.com/capabilities/structured-outputs) currently states that Cloud does not support this feature. [OpenAI's strict-schema documentation](https://developers.openai.com/api/docs/guides/structured-outputs) explains the root-object and required-field restrictions. Sending a schema is a wire-contract implementation, not proof that a particular endpoint enforces it. The constrained cloud measurement is reported separately from the earlier v2 run.

Replay and resume reconstruct spawn admission against the calls created so far, in the same order as live execution: resolve and parse the slice, check inherited scope, reuse an existing digest, then enforce depth and call limits before allocating a new child. They visit the child before checking the parent observation against the next-prompt context budget. Every refused spawn observation must match the regenerated code and reason; nested integrity failures cannot become parent tool refusals. Original v1 code-only observations keep their code-only exception. A legacy terminal failure without a stored message can reproduce the historical fixed `Recorded child refusal` reason; other unverifiable recorded messages fail closed.
